# Experiment 11 - REST API Model Serving

## Aim
Expose the trained classifier through a REST API and validate request/response behavior.

## Requirements
- Core Python dependencies from `requirements.txt`
- Model artifact generated by `python -m mlops_practicals.run_pipeline`

## Procedure
1. Start the API with `uvicorn mlops_practicals.api:app --reload` from the repository root.
2. Open `http://127.0.0.1:8000/docs` or send a request with Postman.
3. Submit valid feature values and an out-of-range input.
4. Measure repeated network requests separately before reporting latency.

Example `/predict` request:

```json
{"Marks": 85, "Attendance": 90, "Study_Hours": 5, "Performance_Score": 86.5}
```

## Observed result
Automated in-process API tests returned HTTP 200 for a valid prediction and HTTP 422 for an invalid feature value. No network latency benchmark was run; see [`OUTPUT.txt`](./OUTPUT.txt).

## Viva questions
1. How should an API handle missing or out-of-range features?
2. Why should confidence scores not be assumed calibrated?
3. Which measurements are needed for a meaningful latency report?

## Concept summary
Model serving wraps prediction in a versioned, validated request/response contract.

## Outcome summary
The prediction endpoint and input validation are covered by automated tests; production network behavior remains unmeasured.
